# Evidence that a test ran in the current invocation

Dated 24 November 2026. This exploratory extension uses a previously examined snapshot. Freeze the following definitions before inspecting marker counts. The prediction endpoints in the earlier manuscript remain as scored.

**Field endpoint.** Census all 84 pinned shards. Restrict the field population to trajectories whose dataset language is Go. At 15 completed rounds, count exact Go package success summary lines in observations linked to a single direct go test command, optionally preceded by one directory change. The denominator counts package-result lines, including repeated reports across runs. The numerator counts explicit cache replays. Separately count timed successes flagged as having no tests to run. The sum gives a ceiling on how many printed successes could represent fresh matching test bodies by subtracting these two categories from all success lines. Report an undefined fraction if the denominator is zero. The unit is a printed package record. A cached package can coexist with fresh work in another package. Cache replay is valid reuse of an earlier result.

Repeat at 30 rounds and for each model/scaffold group. As a sensitivity restrict to exact lines with a tab between ok and the package name. Report counts of observations and trajectories with any success and any cache replay, distinct represented repositories, and output with a mixture of timed and replayed records. Summaries, file contents and repository counts are descriptive for this finite corpus. Prohibit use of resolution labels, patches or agent reasoning. Preserve the Go provider and command restrictions even if few records qualify.

**Controlled endpoint.** Compare the exact same runner command across body-entered and body-not-entered conditions. Independently record entry by a side effect in the first statement of each test body. For Go include first execution, warm replay, forced execution and an unmatched test selector. For Python compare ordinary pass, all skipped, test-body failure and setup error under pytest and unittest. Capture command, exit status and frozen pass/failure parser decisions. A deterministic pair with the same observed projection and different witness labels is a constructive counterexample to identifiability from that projection. Fixtures establish possibility rather than a population error rate.

**Review sensitivity.** At R15 in the existing A+B frame compute the sharp lower and upper extrema of the weighted command-minus-execution *evidence* gap over independent choices of either complete first-round judgment per item. Also allow fieldwise mixing as a more conservative sensitivity. Retain all denominators, including uncertain judgments. This quantifies reconciliation sensitivity conditional on the recorded reviews. It cannot identify an unobserved test body or a shared labeling error. Report all endpoints even if the bounds include zero.

Implementation note following the first census. The first tab sensitivity required a tab immediately after `ok`. Go emits two spaces before that tab. We corrected the implementation to accept a tab anywhere in the separator as specified above and reran all shards. After inspecting the pooled results we added equal-repository weighting, the range after deleting one repository, and co-occurrence of a named verbose case pass with exclusively cached *recognized* package records in an observation. These are descriptive post hoc checks. The last query cannot link a case to a package when output is incomplete.

Additional calibration after the synthetic controls. Use the archived Go 1.25.4 sources for encoding/base32, encoding/base64, hash/adler32, hash/crc32, hash/fnv, math/bits, sort and unicode/utf8. Instrument one existing named test per package using a build overlay. Select the first matching declaration in filename order, excluding files with build directives. Run the selected test cold, warm and with cache bypass. Retain all eight package results. This is a mechanism check within one toolchain.
